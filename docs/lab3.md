# Lab 3. 커넥터 구성 🔍

> **이번 랩 완성물**: 커넥터 도구 + 지침만으로 지원자 **조회·평가·면접질문**이 되는 면접관 에이전트

이 랩 예상 **30분**. 빌드는 적고 **테스트가 많은** 랩 — 프롬프트를 바꿔 가며 관찰하세요.

**왜** — Lab 2의 에이전트는 기준은 알지만 **누가 지원했는지는 모릅니다.** 데이터를 읽는 통로를 붙여, **흐름을 하나도 만들지 않고** 조회·평가·질문이 어디까지 되는지 확인합니다. 오후에 "그래도 흐름이 필요한 이유"를 만나기 위한 **대조군**입니다.

## 준비

Lab 2에서 만든 **면접관 에이전트**를 엽니다. 지금은 기준(지식)은 알지만 "누가 지원했는지"는 모릅니다. 그 데이터를 읽는 **도구**를 붙입니다.

---

## 단계

1. 상단 **[도구](./glossary.html#term-tool)** 탭에서 **+ 도구 추가**를 클릭합니다.

    ![도구 탭 → 도구 추가](../assets/lab3/01.png)

2. **[커넥터](./glossary.html#term-connector)**를 고르고 검색창에 `SharePoint`를 입력합니다.

    ![커넥터 검색 SharePoint](../assets/lab3/02.png)

3. **항목 가져오기(2개 이상)**(Get items)를 선택합니다. ("1개"는 단건 조회용이라 [목록](./glossary.html#term-list) 조회엔 맞지 않습니다.)
    

    ![항목 가져오기(2개 이상) 선택](../assets/lab3/03.png)

4. **연결**이 본인 계정으로 잡혔는지 확인한 뒤 **추가 및 구성**을 클릭합니다. (사이트 주소·목록 이름은 6단계에서 지정합니다.)
    > 연결 객체가 지정되지 않았으면 추가합니다.

    ![연결 확인 후 추가 및 구성](../assets/lab3/04.png)

5. 도구 **설명**에 라우팅 힌트를 입력합니다. (오케스트레이터가 이 설명을 보고 도구를 부릅니다.)

    ```
    지원자 목록에서 지원자 항목을 가져온다. 조회·적합도 평가·면접 질문 등 지원자 정보가 필요할 때 사용한다.
    ```

    ![도구 설명 입력](../assets/lab3/05.png)

    {: .note }
    도구가 돌려준 항목은 오케스트레이터가 **자동으로 답변 근거**로 씁니다

    {: .important }
    사용할 자격 증명 옵션을 `작성자가 제공한 자격 증명`으로 변경시 개발 단계, 테스트시에 용이합니다. 실제 운영시에는 `최종 사용자 자격 증명`으로 변경 후 배포합니다.
6. **입력** 탭에서 **Site Address**에 **`에듀랩`** 를 지정합니다. 이어서 **List Name**도 Lab 1에서 만든 **본인 리스트**를 지정합니다.

    ![입력 구성 b](../assets/lab3/06b.png)


7. 저장 후 우측 테스트를 수행합니다. 변경 내용이 즉시 반영 되도록 새 테스트 세션 시작 버튼 후 `지원자가 몇명이야?` 라는 질문을 통해 커넥터의 연결 여부를 확인합니다.

    ![커넥터 연결 확인 테스트](../assets/lab3/07.png)

    ![커넥터 연결 확인 테스트 b](../assets/lab3/07b.png)

8. 조회가 잘 이루어진다고 하더라도 프롬프트 인식의 정확도 향상을 위해 지침에 다음내용을 추가합니다. 에이전트의 개요 > **[지침](./glossary.html#term-instructions)**에 아래 `## 조회` 섹션을 이어 붙입니다(Markdown). /로 시작하는 `항목 가져오기(2개 이상)` 부분은 chip으로 지정해줍니다.

    ```
    ## 조회
    지원자 정보는 /항목 가져오기(2개 이상) 도구로 가져온다. 기본 조회는 승인된 지원자만 보여주고, 거부·보류는 노출하지 않는다.
    
    ```

    ![지침 조회 섹션 추가](../assets/lab3/08.png)

    {: .note }
    커넥터는 조회 시 **사실상 전부** 가져옵니다. "승인된 사람만"은 도구가 아니라 **지침**이 표시 단계에서 거릅니다 ([가드레일](./glossary.html#term-guardrail)). 단, 표시 단계 차단이라 데이터가 아주 많아지면 엣지케이스에 취약할 수 있습니다(일상엔 충분하고 더 안전한 형태는 흐름을 통한 강제 필터 혹은 [토픽](./glossary.html#term-topic)으로 처리합니다).

9. 테스트 패널에서 `지금 지원자 누구 있어?`를 입력해 지원자 목록이 나오는지 확인합니다.

    ![지원자 목록 응답](../assets/lab3/09.png)

    {: .note }
    지금 시드 지원자는 모두 승인됨이라 전원 나옵니다. **거부·보류가 가려지는 게이트 효과는** 오후에 적재(Lab 4)로 보류 지원자를 만들고 승인(Lab 5)을 거친 뒤 다시 물어보면 또렷이 보입니다.

10. `정재혁 지원자 요약정보 보여줘`처럼 특정 지원자를 물어 상태·요약이 나오는지 확인합니다.

    ![특정 지원자 상태·요약](../assets/lab3/10.png)



11. **+ 도구 추가 → 커넥터 → SharePoint**에서 **경로로 파일 콘텐츠 가져오기**(Get file content using path)를 선택합니다.

    ![경로로 파일 콘텐츠 가져오기 선택](../assets/lab3/11.png)

    ![경로로 파일 콘텐츠 가져오기 선택 b](../assets/lab3/11b.png)



12. **사이트 주소**는 이전 Sharepoint 사이트로 지정하고, **파일 경로**는 `AI로 동적으로 채우기 상태`를 유지합니다. 도구 **설명**에 `이력서 원문을 경로로 가져온다. 면접 질문·정밀 분석에 원문이 필요할 때 사용한다.`를 입력하고 저장합니다.

    ![파일 콘텐츠 도구 설정·설명](../assets/lab3/12.png)

    {: .warning }
    원문 가져오기는 **로딩이 깁니다.** 그래서 매번이 아니라 요청·심층 시에만 부릅니다(2단 구조: 요약=기본·빠름 / 원문=필요할 때·느림).

13. **지침**에 아래 `## 평가·질문` 섹션을 이어 붙이고 **저장 + 게시**합니다.

    ```
    ## 평가·질문
    적합도는 이력서요약을 평가 루브릭(R1~R5)에 대조해 등급(적극추천/추천/면접확인필요/부적합, 기본 미적용)으로 처리한다. 면접 질문·정밀 분석 등 원문이 필요할 때만 /경로로 파일 콘텐츠 가져오기 로 1건 가져온다.
    ```

    ![지침 평가·질문 섹션 추가](../assets/lab3/13.png)

    {: .note }
    등급 어휘(적극추천/추천/면접확인필요/부적합)를 지정하는 이유 : 사전에 정의되지 않은 등급을 "중위 등급 / 상위 등급" 처럼  즉흥으로 만들 가능성이 있습니다.

14. 적합도를 물어 등급 + 평가 축별 근거가 나오는지 확인합니다.

    ```
    정재혁 적합도 평가해줘
    ```

    ![적합도 등급 + 축별 근거](../assets/lab3/14.png)

    {: .important }
    **등급은 지원자 실력이 아니라 수치·사례를 추적합니다.** 요약에 수치가 빠지면 평가기준 R3~R5가 약해지고 등급이 내려가는데, 등급만 보면 그 차이가 안 보입니다. **Lab 5의 승인 HITL이 바로 이 순간을 막는 사전 방어**입니다.

15. 면접 질문을 요청해 요약 기반 질문이 나오는지 확인합니다.

    ```
    정재혁 면접 질문 만들어줘
    ```

    ![면접 질문(요약 기반)](../assets/lab3/15.png)

    {: .note }
    시드 지원자도 **원문(이력서 PDF)이 함께 적재**돼 있어 지금 바로 "원문까지 보고 더 깊게"를 시험할 수 있습니다 — 예: `정재혁 이력서 원문까지 보고 면접 질문 만들어줘`. 

<details markdown="block">
<summary>⚠️ 원문 요청 시 아래 오류가 발생했다면</summary>

> 오류 메시지: 커넥터 'SharePoint'이(가) 코드 500과(와) 함께 HTTP 오류를 반환했습니다.  
> 내부 오류: Internal server error occurred while invoking API.  
> 오류 코드: ConnectorRequestFailure

SharePoint 파일 다운로드 권한이 현재 환경에서 제한돼 있을 수 있습니다. **경로로 파일 콘텐츠 가져오기** 커넥터는 그대로 두고 설정을 비활성화 합니다. 이후 지침의 `## 평가·질문` 블록만 아래 내용으로 **교체**한 뒤 저장·게시합니다.
![경로로 파일 콘텐츠 가져오기 비활성화](../assets/lab3/error1.png)

```
## 평가·질문
적합도는 이력서요약을 평가 루브릭(R1~R5)에 대조해 등급(적극추천/추천/면접확인필요/부적합, 기본 미적용)으로 낸다.
면접 질문도 이력서요약을 기반으로 생성한다.
```

이후 면접 질문 요청이 요약 기반으로 정상 동작하면 계속 진행합니다. 원문 기반 정밀 분석은 환경 권한 설정 후 별도로 재시도할 수 있습니다.

</details>

- [ ] 지침에 `## 조회`·`## 평가·질문` 섹션이 추가·게시됐다

- [ ] 면접 질문이 생성된다(시드도 원문 적재돼 원문 기반 정밀 질문까지 가능)

{: .important }
흐름을 하나도 안 만들었는데 조회·평가·질문이 됩니다 — **"조회와 추론은 커넥터+지침이 처리할 수 있다."** 단, **원문 접근 권한을 막는 건 지침이 아닙니다** 그렇다면 흐름은 왜 필요할까요? 6,7 랩에서 답합니다.
