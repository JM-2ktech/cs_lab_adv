# 스크린샷 촬영 안내

셔터는 사람이 누른다. 이 스킬은 **어디를 어떤 상태로 띄울지 일러 주고, 찍힌 것을 열어 검사하는** 일을 한다.
화면 자체를 브라우저 자동화로 찍지 않는다 — 해상도와 스케일이 교안 컷에 안 맞고, 로그인이 MFA로 막힌다.

무엇을 고쳐야 하는지는 [실측_리포트](../../../_instructions/실측_리포트_2026-09.md), 규칙은 [작업_지침](../../../_instructions/작업_지침.md) 에 있다.

---

## 0. 찍기 전에 — 확정되지 않은 게 둘 있다

**먼저 사용자에게 확인한다. 안 정하고 찍으면 전부 다시 찍는다.**

**① 계정 표시명이 「교육」인가 「에듀」인가.**
`edu@2ktech.co.kr` 의 표시 이름이 지금 **「교육」**이다. 화면 우상단·승인 카드·흐름 실행 기록 등
**거의 모든 컷에 찍힌다.** 「에듀」로 바꿀 거면 촬영 전에 바꾼다.

**② Lab 4 의 정본이 뒤집히는가.**
차기 고객사가 Outlook 을 안 써서 `lab4-alt`(수동 트리거)가 본문이 될 예정이다.
그렇게 되면 **`lab4.md` 의 메일 트리거 화면 14장은 찍을 필요가 없다** — 지우거나 강등될 문서다.
확정 전이면 **Lab 7 부터 찍는다.**

둘 다 답을 받은 뒤에 1로 간다.

## 1. 남은 것을 센다

```bash
grep -rn '!\[촬영:' docs/
```

`촬영:` 으로 시작하는 alt 텍스트 = **아직 제대로 된 컷이 아니다**(다른 랩 것을 임시로 쓰고 있거나 화면이 낡았다).

현재 상태 (2026-09-07 갱신):

| 문서 | 촬영 대기 | 비고 |
|---|---|---|
| `docs/lab4-alt.md` | **5** | 지금의 **Lab 4 본편**. 전부 `assets/lab4-alt/` (07·14·25·27·28) |
| `docs/lab7.md` | 4 | `31 · 32 · 40 · 42` |
| ~~`docs/lab4.md`~~ | 14 | **비활성 — 찍지 않는다.** 아래 참조 |

**찍을 것은 9장이다**(lab4-alt 5 + lab7 4).

`docs/lab4.md`(Outlook 메일 트리거판)는 2026-09-07 에 `nav_exclude` 로 감췄다.
**되살릴 때 그대로 쓸 것이므로 문서도 `assets/lab4/` 도 건드리지 않는다.**
그 14장은 되살리는 시점에 다시 센다.

⚠️ 종전에 lab4-alt 의 대기 컷은 `assets/lab4/` 를 가리켰고, 스킬은 「한 장 찍으면 양쪽이 동시에 해결된다」고
적고 있었다. **이제는 반대다** — 거기 찍으면 되살릴 lab4 에 수동 트리거 화면이 박힌다.
2026-09-07 에 다섯 장을 `assets/lab4-alt/` 로 갈라 두었다. 두 폴더를 섞지 않는다.

사용자에게 **어느 랩부터 할지** 묻고, 그 랩 안에서는 번호 순으로 한 장씩 간다.

## 2. 한 장 찍는 절차

### ① 무엇을 찍는지 먼저 읽는다

이미지 줄만 보면 안 된다. **그 이미지가 붙어 있는 단계의 본문**을 읽어야 무슨 화면인지 안다.

```bash
sed -n '120,135p' docs/lab4.md      # 이미지 줄 앞뒤로 넉넉히
```

그 단계가 지시하는 조작·라벨·값을 그대로 뽑아낸다. 그게 화면에 보여야 할 것이다.

### ② 사람에게 이렇게 말한다

네 가지를 준다. 길게 쓰지 않는다.

```
lab7 40.png — 선행 조건 게이트

  화면 : Copilot Studio > 면접관 에이전트 > 토픽 > 전형단계 변경 > 36번 조건 노드
  상태 : 왼쪽 칸이 수식 모드로 바뀌어 있고 아래 식이 들어가 있을 것
         Topic.AI적합도 = "미적용" || Topic.지원자Record.ApproveStatus.Value <> "승인됨"
         연산자 = 같음, 오른쪽 = true
  담을 것 : 조건 노드 전체. 위아래 노드가 한 줄씩 걸쳐도 된다
  저장 : assets/lab7/40.png  (덮어쓰기)
```

- **화면** — 어느 제품, 어느 메뉴 경로, 어느 노드까지
- **상태** — 무엇이 입력·선택·펼쳐져 있어야 하는가. 접힌 조건 노드처럼 **펼쳐야 보이는 것**을 빠뜨리지 않는다
- **담을 것** — 프레임 범위. 창 전체인지 노드 하나인지
- **저장** — 경로. 이미 있는 파일이면 덮어쓴다고 말해 준다

그리고 기다린다. **여러 장을 한꺼번에 주문하지 않는다** — 검사가 밀리면 잘못 찍은 걸 나중에 알게 된다.

### ③ 찍힌 것을 연다

파일이 왔다고 하면 **Read 로 이미지를 직접 본다.** 이게 이 스킬의 핵심이다.

```
Read assets/lab7/40.png
```

보고서 다음을 확인한다.

- **맞는 화면인가** — ①에서 읽은 단계가 지시한 것이 실제로 보이는가
- **상태가 맞는가** — 값·라벨·펼침 상태. 접혀 있으면 다시 찍는다
- **고객사명·개인정보가 없는가** — 이 저장소는 공개다. 다른 테넌트 이름, 실제 사람 이름·메일이 브라우저 탭·북마크·알림에 걸리지 않았는지 본다
- **계정 표시명이 0번에서 정한 것인가**
- **잘리지 않았는가** — 필요한 UI 가 프레임 밖으로 나갔는지
- **읽히는가** — 글자가 뭉개질 만큼 작지 않은지

문제가 있으면 **무엇이 다른지 한 줄로 말하고 다시 찍게 한다.** 「다시 찍어 주세요」만 말하지 않는다.

### ④ 통과하면 표시를 지운다

alt 텍스트에서 `촬영: ` 만 지운다. 나머지 캡션은 그대로 둔다.

```markdown
![촬영: 선행 조건 게이트 — 수식 모드 조건 입력](../assets/lab7/40.png)
→
![선행 조건 게이트 — 수식 모드 조건 입력](../assets/lab7/40.png)
```

**두 문서가 같은 파일을 쓰면 양쪽 다 지운다.** `assets/lab4/` 의 6장이 그렇다 —
`lab4.md` 와 `lab4-alt.md` 를 함께 연다.

캡션이 화면과 안 맞으면 **캡션도 이때 고친다.** 「①·②·③」처럼 순서를 가리키는 캡션은
실제 화면의 순서와 맞는지 특히 본다.

## 3. 랩 하나를 끝내면

```bash
bundle exec jekyll build
python _instructions/linkcheck.py     # ADVANCED · OTHER · step numbering 셋 다 0
```

그리고 커밋한다. **랩 단위로 끊고, `main` 에 바로 밀지 않는다** — `shoot/labN` 브랜치를 파서 PR 로 낸다.
제작자가 같은 문서의 본문 교정을 따로 진행하고 있다.

```
docs(lab7): 조건 게이트 컷 4장을 다시 찍는다

축소로 40·42 가 다른 단계 컷을 빌려 쓰고 있었다.
```

## 4. Lab 7 은 고아 컷을 함께 정리한다

58단계로 줄이면서 참조가 끊긴 컷이 11장 있다.

```bash
for f in assets/lab7/*.png; do grep -q "$(basename $f)" docs/lab7.md || echo "orphan: $f"; done
```

`34 35 36 36b 41 42b 45 45b 46 47 32b` — **지울지 되살릴지 사용자에게 묻는다.**
줄인 단계로 되돌아갈 일이 없다면 지우는 쪽이 맞다. 지운다면 같은 커밋에 넣는다.

## 하지 않는 것

- **브라우저 자동화로 대신 찍지 않는다.** 스케일이 안 맞고 MFA 로그인이 막힌다
- **여러 장을 한꺼번에 주문하지 않는다.** 한 장 찍고 검사하고 다음으로 간다
- **파일이 왔다는 말만 믿고 표시를 지우지 않는다.** 반드시 Read 로 열어 본다
- **본문 문장을 이 스킬에서 손보지 않는다.** 캡션은 고치되, 본문 교정은 실측 리포트를 보고 따로 한다
