## Lab 2 — 지식과 지침

### 통과한 것
11·12·13단계(적합도 평가 / 인재상 / 이력서 추출 항목)는 각각 평가 루브릭·회사 지침·평가 루브릭을 근거로 정확히 답한다. 인용도 붙는다.

### 고쳐야 하는 것

1. **10단계가 성립하지 않는다.** `백엔드 채용 기준이 뭐야?` 에 대해 "백엔드 직군에 특화된 JD 문서는 조회되지 않았다"며 공통 기준으로 답한다. 교안은 「JD 근거 답변」을 기대한다. 검색 쿼리는 JD 를 겨냥했는데 인용은 평가 루브릭·채용 가이드에서만 올라왔다.
2. **14단계의 경계 설명이 절반만 된다.** `승인된 지원자 목록 보여줘` 는 "실시간 데이터는 별도 시스템에 있고 접근이 안 된다"고 잘 답하지만, `김지훈 지원했어?` 는 **"미지원이거나 이름 오타이거나 처리 지연"** 이라며 마치 조회한 것처럼 답한다. 완료 기준 「답 못 하고 경계를 스스로 설명한다」가 이 질문에서는 거짓이다.
3. **지식 PDF 안에 저작 메모가 들어 있고 RAG 가 그걸 인용한다.** 인용 청크에 「이중 용도 문서」 「PA-01 추출 스키마의 명세」 「상시 RAG 코퍼스」 「직무기술서(JD).md 로 분리되었다」 같은 내부 설계 서술이 그대로 나온다. **수강생 화면에 노출된다** — 지식 PDF 를 다시 만들어야 한다.
4. **내부 식별자가 답변에 새어 나온다.** 13단계 답변이 「PA-01 추출 스키마」로 시작한다. 원인은 지식 문서 본문에 `PA-01` 이 적혀 있어서다 — 지침으로 막기보다 문서에서 빼는 쪽이 맞다.
5. **4단계의 「에이전트 메시지에 대한 사용자 반응 수집」 토글이 없다.** 설정 → 생성형 AI 의 지식 섹션에는 「근거 없는 응답 허용하기」와 「웹의 정보 사용」 둘뿐이다.
6. **파일명에 공백이 있으면 지식 소스 URL 검증에 걸린다.** `.../adv/회사 지침 문서.pdf` 를 넣으면 "잘못된 URL입니다"가 뜨고 「그래도 추가하시겠습니까?」를 눌러야 통과한다. 항목 찾아보기로 고른 것은 `%20` 으로 인코딩돼 들어가 이 경고가 없다.

## Lab 3 — 도구

### 통과한 것
7·9·10단계 모두 동작한다. `지원자가 몇명이야?` → 10명 표, `지금 지원자 누구 있어?` → 요약 포함 10명, `정재혁 상태 알려줘` → 직무·경력·검토상태·승인상태·보류여부.

### 반드시 고쳐야 하는 것

**원문 도구가 404 로 죽는다.** 12단계가 「파일 경로는 AI로 동적으로 채우기 상태를 유지」라고만 하고 경로 규칙을 주지 않는다. AI 가 `이력서링크` 에서 경로를 추론하면서 **라이브러리 세그먼트 `DocLib/` 를 빼먹는다.**

```
Site Address : https://2ktech.sharepoint.com/sites/edulab
File Path    : 이력서샘플/20260623_004855_0175b72c.pdf   ← DocLib/ 누락 → 404
```

지침에 한 줄 추가해 해결했다(실증 완료).

```
파일 경로는 이력서링크에서 사이트 주소를 제외한 나머지를 그대로 쓴다. 라이브러리 폴더를 생략하지 않는다.
```

고친 뒤 `정재혁 이력서 원문까지 보고 면접 질문 만들어줘` 가 성공하고, 응답에 **「경력: 7년 3개월 (시니어)」** 가 나온다 — 리스트 요약에는 「7년간 근무」만 있으니 원문 PDF 에서 온 값이다.

### 교안에 없는 화면·단계

1. **6단계 목록 제안이 바로 안 뜬다.** 「List Name에 대한 제안 사항을 찾을 수 없습니다」가 먼저 나오고, **「새로 고침」을 누른 뒤 드롭다운을 다시 열어야** 리스트가 나온다.
2. **「사용할 자격 증명」은 「추가 세부 정보」를 펼쳐야 보인다.** 5단계 콜아웃은 위치를 알려주지 않는다.
3. **자격 증명을 「작성자가 제공한 자격 증명」으로 바꾸면 게시 시 경고가 붙는다** — 「에이전트가 작성자의 자격 증명을 사용하는 도구를 실행합니다」.
4. **원문 도구 첫 호출에 연결 승인 카드가 뜬다** — 「계속하려면 연결하세요 / 허용 / 취소」. 두 번째 도구의 자격 증명을 기본값(최종 사용자)으로 두었기 때문. **수강생이 여기서 멈춘다.**
5. **사이트 드롭다운 맨 위에 「에듀랩」이 뜬다.** 6단계의 「목록에 사이트가 안 보이면 URL을 직접 입력」 안내가 이 환경에서는 불필요하다.
6. 도구 실제 이름은 **「경로를 사용하여 파일 콘텐츠 가져오기」** — 교안은 「경로로 파일 콘텐츠 가져오기」로 적었다.

> **정본이 뒤집힌다.** 차기 고객사가 Outlook 을 쓰지 않아 적재 흐름은 [lab4-alt.md](../docs/lab4-alt.md)(수동 트리거·파일 업로드)로 간다. 지금은 lab4(메일 트리거)가 본문이고 alt 가 대안이다. 이 관계가 뒤집혀야 한다 — 상세는 아래 §정본 교체.

### lab4(메일 트리거) 1~9단계

1. **1~4단계는 이미 되어 있었다.** `채용지원[샘플]` 폴더(6통)와 「이력서 샘플 분리 규칙」이 edu 계정에 남아 있다. 재현이 아니라 확인만 했다.
2. **8단계 — 고급 매개 변수를 「펼칠」 필요가 없다.** 새 UI 는 트리거 추가 시점에 이미 4/9 가 펼쳐져 나온다(첨부 파일 포함 · 중요도 · 첨부 파일이 있는 항목만 · 폴더). 교안은 「펼쳐 설정합니다」라고 적었다.
3. **9단계 — 저장 시 이름 입력 창이 없다.** 「초안 저장」을 누르면 「초안 흐름을 저장했습니다」만 뜨고 이름을 묻지 않는다. 흐름 이름은 **상단 제목을 직접 편집**해야 한다.
4. **버튼 이름이 「저장」이 아니라 「초안 저장」이다.** 옆에 「게시」가 따로 있다.
5. **같은 이름의 흐름이 이미 환경에 있다.** 제작자가 만든 `적재 흐름` 과 `적재 흐름 (수동 트리거)` 가 남아 있어, 교안대로 `적재 흐름` 으로 저장하면 목록에서 구분이 안 된다.

### lab4-alt 1~9단계

1. **3단계 — 「필수로 표시」 조작이 없다.** 입력이 기본으로 필수이고, 「…」 메뉴에는 「필드를 **선택 사항으로** 설정」만 있다.
2. **3단계 — 버튼 이름이 다르다.** 교안 「+ 새 매개변수 추가(Add an input)」 → 화면 **「+ 입력 추가」**.
3. **4단계 — 저장 시 이름 입력 창이 없다.** lab4 3번과 같다.
4. **7단계 — 드롭다운에 기존 「이력서 요약 프롬프트」가 이미 보인다.** 교안은 새로 만들라 하지만 수강생이 기존 것을 고를 여지가 있다.
5. **8단계 — 샘플 업로드가 선택이 아니라 필수다.** 출력을 JSON 으로 바꾸면 「JSON 형식을 새로 고치려면 저장하기 전에 프롬프트를 테스트해야 합니다」가 뜨고 **저장이 잠긴다.** 교안은 "업로드해 두면 바로 테스트해 볼 수 있습니다"라고 선택처럼 적었다.
6. **8단계 — 프롬프트 이름을 정하는 자리가 안 보인다.** 교안은 「이후 프롬프트의 이름을 입력합니다」라 하는데, 디자이너는 `사용자 지정 프롬프트 2026. 9. 1. 오후 2:41:47` 같은 자동 이름으로 저장된다.
7. **테스트가 Copilot 크레딧을 쓴다.** 1회 0.5 크레딧, 5.3초. 교안에 비용 언급이 없다 — 수강생 수만큼 곱해진다.
8. **9단계 — 동적 콘텐츠에 `이력서원본` 이 아니라 `파일 콘텐츠` 로 뜬다.** 트리거에서 바꾼 입력 이름이 동적 콘텐츠 목록에 반영되지 않는다.

### lab4-alt 10~28단계

10. **16단계 — 「체크한 컬럼만 나타납니다」가 틀렸다.** 고급 매개 변수가 처음부터 **「10/12 표시 중」** 이다. 필수 컬럼(AI적합도·요약승인상태·전형단계·보류여부)은 체크하지 않아도 이미 입력 칸으로 나와 있다. 16번 본문의 7개 체크 지시와 뒤따르는 콜아웃을 함께 고쳐야 한다.

## Lab 5 — 승인 흐름

1~17단계를 완료하고 **게시했다.** 흐름 이름 `승인 흐름`. 18~20단계(실제 발송)는 실행하지 않았다.

### 반드시 고쳐야 하는 것

**① 10단계 콜아웃이 사실과 반대다.** 교안은 이렇게 적었다 — 「**제목은 지정하지 않습니다.** 목록의 제목 컬럼을 필수로 두지 않았기 때문에 이 칸이 아예 나타나지 않습니다.」

실제로는 **목록을 고르는 순간 `제목 *` 칸이 필수로 나타나고, 비워 두면 「'제목'은(는) 필수입니다」 오류가 남는다.** 「모두 지우기」를 해도 사라지지 않는다(기본 매개 변수다). **이대로 두면 게시가 막힌다.**
해결 — **트리거의 `제목` 칩을 그대로 넣는다.** 원래 값을 다시 쓰는 것이라 부작용이 없다. 이 조작이 교안에 없다.

**② 16단계 fx 「식 삽입」이 본문(리치 텍스트)에서는 먹지 않는다.** 「식 삽입」으로 긴 `if/coalesce/trim` 식을 넣고 「추가」를 눌러도 **본문에 아무것도 안 들어간다.** 화면에는 들어간 것처럼 보이지만 **「코드 보기」로 확인하면 사유 자리가 비어 있다.** 두 번 시도해 두 번 다 실패했다.
해결 — 본문 툴바의 **`</>`(코드 보기 토글)로 HTML 소스 모드로 바꾼 뒤 `@{ }` 로 감싸 직접 타이핑**한다.

```
@{if(empty(trim(coalesce(items('For_each')?['comments'],''))),'담당자가 별도 의견을 남기지 않았습니다. 자세한 사항은 본 메일 회신으로 문의해 주시기 바랍니다.',items('For_each')?['comments'])}
```

**「코드 보기」로 검증하는 절차를 교안에 넣어야 한다.** 안 그러면 수강생은 사유가 빈 채로 게시하고, Lab 5 의 핵심인 폴백이 통째로 빠진 것을 모른다.
※ 이것이 **자동화 한계인지 실제 결함인지는 아직 모른다** — 사람이 마우스로 한 번 해 볼 것(§손으로 확인할 것).

## Lab 6 — 두 겹 게이트

> ⚠️ **흐름이 저장되지 않았다.** 1~10단계의 조작을 화면에서 확인했지만, 「초안 흐름을 저장했습니다」 배너가 여러 번 떴는데도 **흐름 목록에 남지 않았고**, 면접관 에이전트의 도구에도 지침의 칩 호출에도 나타나지 않는다. 아래 관찰은 전부 유효하지만 **흐름 자체는 1단계부터 다시 만들어야 한다.**

### ⚠️ 6·7단계 — fx 편집기 대신 `@{ }` 로 직접 쓴다

교안은 조건의 왼쪽 칸을 **fx 모드로 전환**해 식을 넣으라고 한다. 이 경로에 함정이 둘 있다.

**① fx 「식 삽입」이 값을 반영하지 않는다.** Lab 5 16단계와 같은 증상이다(§손으로 확인할 것).

**② fx 편집기의 「동적 콘텐츠」 탭을 쓰면 `For each` 가 끼어든다.** 교안 6번 콜아웃이 「이름이 다르면 **식 편집기 자동완성으로 확인**하세요」라고 안내하는데, 이 환경에는 **자동완성이 없고**(`outputs('` 까지 쳐도 후보가 안 뜬다) 동적 콘텐츠 탭만 있다. 거기서 항목 가져오기의 필드를 고르면 참조가 `items('For_each')?['ID']` 로 들어오면서 **캔버스에 For each 가 자동 생성되고 조건이 그 안으로 들어간다.**
**되돌리려면 For each 를 지워야 하는데, 지우면 안에 든 조건이 함께 사라진다.** 두 겹 게이트를 다 만든 뒤에 발견하면 처음부터 다시다.

**실제로 통한 방법** — 조건의 값 칸(리치 텍스트)에 **`@{ }` 로 감싸 직접 타이핑**한다.

**단, 타입을 맞춰야 한다.** `@{length(...)}` 는 **문자열** `"1"` 을 돌려주는데 오른쪽 칸에 `1` 을 넣으면 **숫자** `1` 로 저장돼 `equals` 가 언제나 거짓이 된다. 오른쪽에 `@{1}` 을 넣어 문자열로 맞추면 **저장할 때 값이 사라진다.** 그래서 비교 자체를 식 안으로 넣었다 — 이 형태가 안정적이다.

```
왼쪽 : @{equals(length(outputs('항목_가져오기(2개_이상)')?['body/value']),1)}
연산자: 다음과 같음
오른쪽: True
```

7단계는 원래 문자열 비교라 교안 식을 그대로 `@{ }` 로 감싸면 된다.

```
왼쪽 : @{first(outputs('항목_가져오기(2개_이상)')?['body/value'])?['ApproveStatus/Value']}
오른쪽: 승인됨
```

**액션 내부명은 교안이 적은 `항목_가져오기(2개_이상)` 이 맞다** — 공백만 `_` 로 바뀌고 괄호는 그대로다.
**타이핑 요령** — 식 안의 `/` 를 치면 동적 콘텐츠 메뉴가 뜬다. **Esc 로 닫으면 `/` 는 남으므로** 그대로 이어 치면 된다.

### ⚠️ 8단계 — 「모두 지우기」 지시가 없다

사이트·목록을 고르면 고급 매개 변수 4개가 자동으로 붙는다(AI적합도 `미적용` · 요약승인상태 `승인대기` · 전형단계 `검토중` · 보류여부 `아니요`).
**이대로 두면 Lab 5 에서 승인한 값이 `승인대기` 로 되돌아가고 전형단계도 리셋된다 — Lab 6 이 Lab 5 를 되돌리는 셈이다.** 반드시 「모두 지우기」 후 **AI적합도 Value 만** 다시 체크해야 한다.

**8단계 — 여기서도 `제목 *` 이 필수로 나타난다**(Lab 5 10단계와 같다). 조회 결과의 제목을 그대로 넣으면 된다.
```
@{first(outputs('항목_가져오기(2개_이상)')?['body/value'])?['Title']}
```

### ⚠️ 10단계 — 「에이전트에게 응답」은 검색으로 안 나온다

`응답`·`에이전트`·`회신`·`반환`·`Respond` 어느 것으로 검색해도 나오지 않는다. `응답` 으로 검색하면 **HTTP 의 「응답」**(상태 코드·헤더·본문)이 잡히는데 이건 다른 액션이다.

**경로 — 작업 추가 → 필터 「기본 제공」 → 커넥터 「기술」 → 「에이전트에게 응답」.**
트리거(`에이전트가 흐름을 호출할 때`)와 같은 **「기술」 커넥터**에 들어 있다. 교안 10단계는 「에이전트에게 응답을 추가합니다」라고만 적어 이 경로가 없다 — **수강생이 못 찾거나 HTTP 응답을 잘못 넣는다.**

### 교안과 다른 화면

1. **트리거에 「익스프레스 모드(프리뷰)」 토글이 새로 생겼다.** 피드백 줄(👍👎)까지 트리거 카드 안에 붙어 있다. 기본은 꺼짐. 교안 01 스크린샷에 없다 — **켜면 무엇이 달라지는지 확인이 필요하다.**
2. **2단계 입력 유형은 텍스트·파일·숫자·날짜 4종이다.**
3. **3단계는 입력을 하나씩 추가한다.** 첫 입력을 만들고 이름·설명을 채운 뒤 「+ 입력 추가」를 다시 눌러야 두 번째가 생긴다. 교안 03 스크린샷은 둘이 이미 있는 상태다.
4. **5단계 고급 매개 변수는 6종이다** — 필터 쿼리 / 정렬 기준 / 최대 개수 / 보기별로 열 제한 / 항목을 폴더로 제한 / 중첩된 항목 포함.

### 무너지는 것

1. **Lab 3 의 「승인된 지원자만」 규칙이 검증되지 않았다.** `지원자가 몇명이야?` 에 10명 전원이 나왔는데, 전원이 `승인대기` 이므로 지침대로면 **0명이 맞다.** 에이전트가 필터를 적용하지 않았거나 「승인대기」를 승인으로 읽었다.
2. **Lab 5 의 「앞 랩과의 연결」 문단이 사실과 다르다.**
3. **Lab 5 거부 테스트(20단계)를 시드 항목으로 못 한다.** 받는 사람이 빈값이라 메일 보내기가 실패한다.

## 손으로 확인할 것 (자동화로 판별 못 했다)

실측은 브라우저 자동화로 했다. 아래 둘은 **사람이 마우스로 한 번 해 보면 바로 판별된다.** 교안을 고치기 전에 확인이 필요하다.

1. **fx 「식 삽입」 → 「추가」가 값을 반영하지 않는다** (Lab 5 16단계, Lab 6 6단계). 자동화로는 두 번 다 실패했고 「코드 보기」로 빈 것을 확인했다. **자동화 한계일 수 있다.** 마우스로 되면 교안은 그대로 두고 「코드 보기로 확인」 절차만 추가하면 된다. 마우스로도 안 되면 `@{ }` 직접 타이핑을 본문에 넣어야 한다.
2. **조건의 오른쪽 값이 편집 중에 비워지는 일이 있었다.** 저장 뒤에는 유지된다 — 저장 전 다른 노드를 건드리면 날아가는 것으로 보인다.
